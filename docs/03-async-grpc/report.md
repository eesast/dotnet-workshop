# 异步 gRPC 日志分析系统实现报告

## 一、 功能介绍

本项目在之前本地日志分析器的基础上，成功升级为了基于 gRPC 框架的“客户端-服务端”网络架构。主要实现了以下核心功能：

1. **服务端日志处理代理 (AgentSession)**：
   - 实现了响应各种网络请求的方法。
   - 能够将底层系统抛出的异常（如路径非法、并发度为负数等）拦截，并转化为标准的网络状态码（如 `INVALID_ARGUMENT`, `DIRECTORY_NOT_FOUND` 等）返回给客户端。
   - 针对结果获取，实现了服务端的流式（Streaming）返回逻辑，先发送全局状态（Header），再循环发送具体的日志内容（LogEntry）。

2. **远程异步客户端 (RemoteCli)**：
   - 全面采用了 `async/await` 异步编程模型，保证在等待网络响应时控制台不会卡死。
   - **切换目录 (Change Directory)**：向服务器发送路径，并接收服务器返回的当前绝对路径和文件列表。
   - **显示文件 (Show Log Files)**：通过网络请求获取当前远端工作目录下的所有日志文件。
   - **执行分析 (Analyze)**：支持全局分析和部分文件分析，将用户输入的并发度等参数打包发送，并根据服务器返回的状态码判断任务是否成功启动。
   - **流式接收结果 (Get Analysis Result)**：建立流式通道，根据服务器发回的数据包类型（Header 或是具体的日志行），分别进行状态打印和逐行解析展示。

## 三、问题回答
**问题 3.1：你认为，你在开发网络应用程序，与你在以往开发非网络应用程序的区别在哪里？网络应用程序的开发存在哪些额外的难点？存在哪些额外的复杂之处？**

**答：**
> 核心区别在于数据通信： 本地程序直接在内存中传递对象，而网络程序必须将数据打包
> 主要难点在于异步逻辑： 网络通信存在延迟，为了不让程序等待卡死，必须使用 async/await 等异步编程模型
> 额外复杂之处在于极高的容错要求： 服务端作为常驻程序，绝不能因为用户的错误输入或内部小错误而崩溃。
